Crypto P2P Selling Platform

A peer-to-peer marketplace where users buy and sell crypto directly with each other, protected by escrow — built end to end, frontend and backend.

Laravel Bootstrap Redis Nginx PHP 8.4 MySQL

Role

Full Stack Developer

Stack

Laravel · Bootstrap

Core

Escrow-backed P2P

Overview

Instead of trading against an order book, users here trade directly with each other: a seller posts an advert with their price and payment methods, a buyer takes it, and the platform holds the crypto in escrow while the two settle payment between themselves.

This one I built as a full stack developer — the Bootstrap frontend as well as the Laravel backend, the database design, the escrow flow and the wallet layer.

Key Features

  • Buy & sell adverts — users post offers with their own price, limits and accepted payment methods.
  • Escrow protection — the seller's crypto is locked by the platform the moment an order opens, and only released once payment is confirmed.
  • Order state machine — opened → paid → released → completed, with cancellation and expiry handled at every step.
  • In-order chat — buyer and seller communicate inside the order to confirm payment.
  • Dispute resolution — either side can raise a dispute, which routes to an admin panel for arbitration.
  • Secure wallet management — deposits, withdrawals and balances backing every trade.
  • Reputation — completion rate and ratings so users can judge who they're trading with.

What I Did

  • Built the entire platform — frontend (Bootstrap, JavaScript) and backend (Laravel, MySQL).
  • Designed and implemented the peer-to-peer trading system: adverts, order matching and the full order lifecycle.
  • Implemented the escrow mechanism that locks seller funds for the duration of an order.
  • Built the dispute flow and the admin arbitration screens behind it.
  • Implemented secure wallet management for deposits, withdrawals and balances.
  • Used Redis for caching and deployed behind Nginx on an Ubuntu VPS.

Challenges & How I Solved Them

1

Nobody can be trusted with the other side's money

Escrow is the whole product. Crypto is locked out of the seller's spendable balance at order creation and can only move to the buyer on confirmed payment, or back to the seller on cancellation — never both.

2

Orders that go quiet

A buyer who opens an order and disappears would lock a seller's funds forever. Orders carry a payment window and auto-cancel on expiry, releasing the escrow back to the seller.

3

Disputes

When the two parties disagree about whether payment landed, the funds stay in escrow and an admin decides — with the order's chat and timeline as the evidence trail.

4

Double-spending a balance

The same balance must not back two adverts at once. Escrow locks and balance mutations run inside database transactions, so funds can only be committed to one order.
